# bdf2ttf

Convert a BDF bitmap font into a TrueType outline font (TTF) using Python and fontTools.

## Install

```bash
python -m pip install fonttools
```

## Usage

```bash
python bdf2ttf.py input.bdf output.ttf
python bdf2ttf.py input.bdf output.ttf --metadata metadata.json
python bdf2ttf.py input.bdf output.ttf --metadata metadata.json --upm 1600
python bdf2ttf.py input.bdf output.ttf --metadata metadata.json --features shaping.fea
```

Run `python bdf2ttf.py --help` for all command-line options.

## Metadata JSON

Start with `metadata.example.json`. Name fields can be plain strings or maps of
fontTools language codes (for example `en`, `zh`, `zh-tw`, `ja`) to localized strings. Unsupported language codes may be skipped by fontTools for some platform-specific name records. Supported name IDs include familyName,
styleName, fullName, copyright, trademark, manufacturer, designer, description,
vendorURL, designerURL, licenseDescription, licenseInfoURL, sampleText, and several
typographic-family fields supported by fontTools. The separate `vendorID` field sets
`OS/2.achVendID` and must be exactly four printable ASCII characters. It is an
identifier, not the readable manufacturer name. `manufacturer` (name ID 8) is
the person/company behind the font; `trademark` (name ID 7) is an optional
trademark notice. Only provide a trademark notice when appropriate. Use your own
vendor identifier; `NONE` is only a placeholder.

Use PostScript-safe ASCII for `psName`. If omitted, a basic name is derived
from the family and style names.

## What the converter does

- Parses BDF glyph encodings, bitmap rows, bounding boxes, and horizontal advances.
- Converts set-pixel runs into rectangular TrueType contours.
- Builds a Unicode cmap and standard TTF tables.
- Recalculates OS/2 Unicode range and code page range bits from the actual cmap.
- Optionally compiles an OpenType feature file to add GSUB/GPOS rules.

## Limitations and complex-script plan

This is an initial converter, not a complete font-shaping system.

- It does not infer Arabic joining forms or mark attachment positions automatically.
- Combining marks with BDF zero advance can be represented as glyphs, but correct
  placement requires GPOS mark-to-base / mark-to-mark anchors.
- Arabic and similar scripts need contextual substitutions in GSUB (`isol`, `init`,
  `medi`, `fina`, and sometimes `rlig`) plus positioning rules in GPOS.
- To begin experimenting, provide an OpenType feature file with `--features`.
  The feature file must refer to glyph names generated by this converter, e.g.
  `uni0627` for U+0627. Since BDF encodings are converted to `uniXXXX` or `uXXXXX`,
  write feature rules using those names.
- A future version should accept explicit anchor data and joining-form mappings in
  JSON, then generate mark classes and contextual GSUB rules. Do not try to infer
  these reliably from bitmap pixels alone.

## Important details

- BDF is parsed as ASCII; this matches standard BDF text files.
- Unencoded glyphs are ignored, and duplicate Unicode encodings keep the first glyph.
- Each set pixel becomes part of a rectangular contour. Adjacent runs are merged
  where possible; this keeps the TTF smaller while preserving the pixel grid.
- Code page ranges are heuristic metadata derived from code-point coverage. They
  indicate likely character-set support, not proof that all characters required
  by a code page are present.
- Always test generated fonts in the applications and scripts you intend to support.
